# GSSceneRefine: only top view vs dual-orthographic views (Stage-1 ROI ablation)

## Scientific question

Can one manually drawn top-view polygon, extruded along the vertical dimension, replace the two-view interaction without unacceptable ROI redundancy or reduced final R3 quality?

### Controlled comparison

- Same native COLMAP Gaussian PLY and complete SfM/Poisson references.
- **Identical** top polygon, origin, axes and scene orientation.
- A (top-only): omit all facade polygon constraints. This is an infinite polygon prism mathematically; finite Gaussian positions supply its effective vertical extent. No arbitrary height caps.
- B (dual-view): original confirmed ROI JSON with all views unchanged.
- Run identical GSSceneRefine R3 Stage A + Stage B to each ROI **independently**. No mask copied from one condition to the other.
- Export R0 and R3 models for both, plus the R0/R3 differences and a CSV/JSON summary. The original ROI is unchanged.

**Important:** Having more Gaussians does not prove higher scene completeness, nor does a disagreement between outputs prove an error. The comparisons are descriptive unless an independent target mask or quality reference is supplied.

## Outputs

In `--output-dir`:

- `roi_top_only.json`, `roi_dual_view.json` — auditable ROI polygons; original JSON not touched
- `top_only/gaussians_R0.ply`, `top_only/gaussians_final_R3.ply` and R3 study diagnostic outputs
- `dual_view/gaussians_R0.ply`, `dual_view/gaussians_final_R3.ply` and R3 study diagnostic outputs
- `R0_only_top_not_dual.ply` — Gaussian centers admitted by A's initial prism but not by B's initial intersection
- `R3_only_top_not_dual.ply`, `R3_only_dual_not_top.ply` — methods' final differences (empty files are not written)
- `ablation_summary.csv`, `ablation_summary.json` — counts, mask overlap and method-specific R3 recovery statistics
