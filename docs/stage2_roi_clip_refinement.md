# GSSceneRefine Stage 2: ROI crossing-triangle adaptive refinement hotfix

2026-11-07 · In-place patch based exclusively on the previously delivered local `GSSceneRefine_stage2_roi_handoff.zip`. This patch does **not** fetch, merge, or overwrite GitHub branches or change Stage-1 algorithms.

## Why the reported error occurs

The `--surface-only` fallback first sampled the signed ROI field at ORIGINAL Poisson vertices, then linearly clipped each triangle. With a large/concave triangle, all three vertices may lie outside the ROI even though the interior of the triangle crosses the ROI. The previous safety check correctly detected **4 conflicting probes** and stopped, but lacked an automatic local-resampling path. These are 4 query points, not 4 Gaussians or necessarily 4 distinct triangles.

## Changes

- `gsrefine/geometry/roi_surface.py`: selectively refine **only** triangles with opposing true vs. linearly interpolated ROI signs at centroid/edge probes. Edge-midpoints are shared with neighboring faces; templates for 1/2/3 split edges keep a conforming triangulation and preserve face winding. New vertices re-evaluate the original signed ROI + bounded R3 support field. Once sample conflicts vanish, the existing piecewise-linear ROI clipping proceeds. This operates on a working copy; Stage-1 Poisson and ROI are unchanged.
- `gsrefine/cleanup/direct_sdf.py`: adds three *generic* safety-budget parameters and updates the geometry cache algorithm signature, so a cache generated by the previous algorithm cannot be silently reused. The sealed Poisson algorithm, Gaussian SDF threshold, and original `gaussian_roi.ply` input remain unchanged.
- `tests/test_stage2_roi_adaptive_clip.py`: checks fully-outside source vertices with interior ROI crossings, source immutability, shared-edge conformity, triangle winding, clipping accuracy on a synthetic axis-aligned ROI, failure on exhausted budgets, no unnecessary refinement for a linear half-space, and Stage-2 fallback integration.

The adaptive process performs **finite probe checks**, not mathematically exact clipping of arbitrary curved/concave 3D implicit regions. If conflicts persist within the configured budget, it **stops** rather than outputting potentially erroneous geometry. All downstream topology, volume, and COLMAP-camera checks remain in place.

## Optional generic safety settings

These keys can be set in the existing `stage2_cleanup` section of the effective runtime YAML for controlled research cases (or left at built-in defaults):

```yaml
stage2_cleanup:
  roi_crop_max_refinement_levels: 6
  roi_crop_max_marked_faces_per_level: 10000
  roi_crop_max_extra_faces: 200000
```

These numbers are resource/safety budgets, **not** a change to the scientific SDF threshold. If a scene continues to fail, investigate the reported conflict and cut topology before increasing the budget. Never bypass validation or silently edit source Poisson triangles. Runtime artifacts remain under the original `--output-dir`; neither the Git repository `runs/` directory nor historical experiments are modified or deleted.
